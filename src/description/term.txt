### Glossary of Technical Terms

This document explains the Machine Learning and Statistics terms used in this project's documentation and code.

---

#### 1. General Machine Learning Concepts

*   **Machine Learning Paradigms**: Different approaches to how an AI learns. This project uses **Genetic Algorithms** (search-based) and **Reinforcement Learning** (experience-based).
*   **Neural Network Architecture**: The structural design of the AI's "brain." Here, a **Multi-Layer Perceptron (MLP)** is used.
*   **Multi-Layer Perceptron (MLP)**: A classic neural network consisting of an input layer, one or more hidden layers, and an output layer. It uses mathematical weights and biases (parameters) to process information.
*   **Hidden Layer**: A layer of neurons between the input and output in a neural network that allows the model to learn complex, non-linear patterns.
*   **Weights and Biases (Parameters)**: The internal numerical values that a neural network "adjusts" during training. Weights determine the strength of connections between neurons, and biases shift the activation.
*   **Policy**: A strategy or mapping that tells the agent which action to take based on its current observation of the environment.
*   **Observation Space (Input)**: The specific set of information the AI "sees" at each step (e.g., distances to walls, positions of players).
*   **Ray-casted distances / Ray Marching**: A technique where "rays" are sent out from the agent's position in different directions to calculate the distance to the nearest obstacle (wall or trail).
*   **Action Space (Output)**: The set of all possible moves the AI can make. This project uses **Discrete Actions** (e.g., Straight, Turn Left, Turn Right).
*   **One-Hot Encoding**: A method to represent categorical data (like "Heading North") as a binary vector (e.g., `[1, 0, 0, 0]`) so the neural network can process it.
*   **Normalization**: Scaling numerical values (like coordinates or distances) to a standard range (usually 0 to 1) to ensure the neural network treats different inputs with equal importance.
*   **Baseline**: A simple model or scripted strategy (like the "Greedy" controller) used as a point of comparison to measure how much the AI has improved.
*   **Batch Processing / Vectorization**: Running many game environments simultaneously in a single mathematical operation (using NumPy/Numba) to dramatically speed up training.

---

#### 2. Genetic Algorithms (GA)

*   **Genome**: A complete set of parameters (weights and biases) for one neural network, represented as a long list of numbers.
*   **Population**: A group of different genomes being tested and evolved at the same time.
*   **Generation**: One full cycle of evaluation, selection, and reproduction in the GA.
*   **Fitness Function**: A formula used to calculate a "score" for each individual based on its performance (e.g., win rate and survival time). It determines which individuals are "fit" enough to reproduce.
*   **Selection / Elites**: The process of choosing the best-performing individuals (elites) from the current population to pass their "genes" to the next generation.
*   **Crossover**: Creating a new "child" genome by combining parts of two "parent" genomes.
*   **Mutation**: Randomly changing a small part of a genome to introduce new behaviors and prevent the population from becoming too similar.
*   **Global Search**: The ability of GA to explore a wide range of possible solutions across the entire "parameter space" without getting stuck too easily.

---

#### 3. Reinforcement Learning (RL)

*   **Proximal Policy Optimization (PPO)**: A state-of-the-art RL algorithm that balances exploration and exploitation. It is designed to be stable and reliable by preventing the policy from changing too drastically in a single update.
*   **Reward Signal**: Numerical feedback given to the agent (e.g., +1 for winning, -1 for dying) to guide its learning process.
*   **Credit Assignment**: The challenge of determining which specific action in a long sequence eventually led to a reward or failure.
*   **Trajectories / Rollouts**: Sequences of observations, actions, and rewards collected by the agent while playing through games.
*   **Gradient-Based Optimization**: A mathematical method for updating the neural network's weights by following the "gradient" (direction) that increases the expected reward.
*   **Value Function**: An internal estimate the RL agent makes about how "good" a current state is (the expected future reward from that point).
*   **Local Optima**: A situation where the AI finds a "pretty good" strategy but fails to find the "best" strategy because it stops exploring new ideas.
*   **Sparse Reward Signal**: When an agent receives feedback only rarely (e.g., only at the end of a long game). This makes it harder for RL agents to learn which specific actions were helpful.
*   **Differentiable Reward Function**: A reward structure that allows for smooth gradient calculations. GA does not require this, making it more flexible for complex fitness metrics.
*   **Gymnasium**: A standard interface (API) used in Reinforcement Learning to connect AI agents to different environments.

---

#### 4. Advanced Concepts

*   **Softmax / Logits**: The raw scores output by the neural network (logits) are converted into probabilities (softmax) to decide which action to take.
*   **Temperature**: A parameter used during sampling; higher temperature makes the AI more "creative" (random), while lower temperature makes it more "focused" (deterministic).
*   **Vectorization (Engine)**: The use of low-level optimizations (like Numba JIT) and array-based math (NumPy) to simulate thousands of game steps per second on the CPU.

#### 5. Tutorial: Reinforcement Learning with PPO in Tron

This tutorial explains how we use **Proximal Policy Optimization (PPO)** to train our Tron agents.

**1. The Goal: Maximizing Rewards**
In Reinforcement Learning, the agent learns by trial and error. Its goal is to maximize the **Reward Signal**.
*   **Winning**: The agent receives `+1.0` if it is the last one alive.
*   **Losing**: The agent receives `-1.0` if it crashes into a wall or a trail.
*   **Survival**: Each step taken without dying counts towards its overall performance, though the primary reward is terminal.

**2. The Environment (Gymnasium Wrapper)**
We use the `TronSingleAgentEnv` (in `src/reinforcement.py`) to bridge our fast game engine with the RL library. 
*   It presents the game as a standard loop: **Observe** -> **Act** -> **Reward** -> **Repeat**.
*   The agent only controls one player; the other players are controlled by a fixed **Opponent Policy** (like the "Greedy" controller) to provide a consistent challenge.

**3. How PPO Learns**
PPO is an "Actor-Critic" method, meaning it maintains two internal models:
*   **The Actor (Policy)**: Decides which move to make (Straight, Left, Right) based on the current distances and player positions.
*   **The Critic (Value Function)**: Estimates how much reward the agent is likely to get from the current position. 

During training, the agent plays many games (called **Rollouts**). It compares the actual rewards it received with what the Critic predicted.
*   If the agent did better than expected, PPO adjusts the Actor's weights to make those actions **more likely** in the future.
*   If it did worse, it makes those actions **less likely**.

**4. Why "Proximal" Optimization?**
The "Proximal" part is PPO's secret sauce. In older RL methods, one bad batch of data could completely ruin a policy by making massive, destructive updates. PPO uses a **Clipped Objective**: it limits how much the policy can change in a single update. This ensures training remains stable and the agent doesn't "forget" everything it learned in a single bad generation.

**5. Training Workflow**
We run PPO using `src/continuous_trainer.py`. The process looks like this:
1.  **Collection**: The agent plays games for a set number of **Steps** (`n_steps`, usually 2048) and stores the data. A "step" is a single action taken by the agent in the game (one tick of the clock).
2.  **Optimization**: The gathered data is used to update the neural network over several **Epochs**.
3.  **Check-pointing**: Every few thousand steps (total **Timesteps**), the model is saved and evaluated against the Greedy baseline to track progress.
4.  **Iteration**: This cycle repeats indefinitely, gradually refining the agent from random moves to expert-level navigation.

#### 6. Clarifying "Steps" and "Timesteps"

In the context of our training logs and code, you will see several terms related to time:

*   **Game Step (Tick)**: A single moment in a Tron game where every player moves forward one square.
*   **n_steps (Collection Window)**: The number of game steps the agent takes to gather experience *before* it stops to learn. If `n_steps` is 2048, the agent "remembers" 2048 moves and their outcomes before updating its brain.
*   **Total Timesteps**: The running total of all game steps taken across the entire training history. This is the primary measure of how much "experience" the agent has. If a model is saved at "1,000,000 timesteps," it means it has seen one million individual moves.
*   **Checkpoint Steps**: A configuration setting (e.g., 50,000) that tells the trainer how often to save the model and run an evaluation.
